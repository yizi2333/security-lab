# security-lab

信息安全学习项目：用 Python 从零实现三个基础安全工具，并串成一条完整的「攻击 → 检测」闭环。

> 作者：Yi Hailin ｜ 2026-09 ｜ 学习用项目，**所有扫描只针对本地靶场**

---

## 三个工具

| 工具 | 说明 | 代码 |
|---|---|---|
| **端口扫描器** | 多线程 TCP 端口扫描，支持单 IP / 域名 / CIDR 网段 | `tools/portscan.py`（163 行） |
| **目录扫描器** | 字典驱动的 Web 路径枚举，区分状态码、识别敏感文件 | `tools/dirscan.py`（123 行） |
| **日志分析器** | 解析 Web access log，统计访问特征并识别 4 类攻击行为 | `tools/loganalyze.py`（175 行） |
| 日志生成器 | 生成带「埋入攻击特征」的测试日志，作为分析器的验收基准 | `tools/genlog.py`（212 行） |
| 靶场生成 | 一键生成本地测试网站和字典 | `tools/setup_lab.py` |
| 自测脚本 | 端口扫描器的 22 个自动化测试用例 | `tools/selftest.py` |

**核心思路：** 三个工具不是孤立的练习，而是一条链路 ——

```
  ① 端口扫描   找出开了哪些服务
        ↓
  ② 目录扫描   从服务里找出隐藏的入口（后台、备份、配置文件）
        ↓
  ③ 日志分析   从服务器视角看：这些攻击在日志里长什么样、怎么被抓出来
```

**②→③ 是可验证的闭环：** 用目录扫描器攻击本地靶场，靶场记下 `access.log`，再用日志分析器把攻击者找出来。**测试数据不是编的，是自己攻击自己产生的。**

## 快速开始

### 环境要求

- Python 3.12（不建议 3.13+，部分库的 wheel 还不全）
- 依赖：`requests`（仅目录扫描器需要）

```bash
git clone https://github.com/yizi2333/security-lab.git
cd security-lab
python -m venv .venv
.venv\Scripts\activate            # Windows
pip install requests
```

### ① 端口扫描器

```bash
# 扫本机常见的几个端口
python tools/portscan.py 127.0.0.1 -p 135,445,8000-8010

# 扫整个网段，100 线程并发，超时 2 秒
python tools/portscan.py 192.168.1.0/24 -p 22,80,443 -t 100 --timeout 2
```

**实测性能（35 个关闭端口）：**

| 线程数 | 耗时 | 加速比 |
|---|---|---|
| `-t 1` | 60.39s | 1.0x |
| `-t 100` | **2.13s** | **28x** |

### ② 目录扫描器

```bash
# 先起本地靶场（另开一个终端）
python tools/setup_lab.py                                  # 生成靶场和字典
python -m http.server 8080 --directory lab                 # 启动靶场

# 然后扫描
python tools/dirscan.py 127.0.0.1:8080 -w wordlists/common.txt
```

**实测性能（71 条字典，目标每响应延迟 50ms）：**

| 线程数 | 耗时 | 加速比 |
|---|---|---|
| `-t 1` | 4.06s | 1.0x |
| `-t 50` | **0.43s** | **9.5x** |

### ③ 日志分析器

```bash
# 生成一份 1000 行、埋了 4 类攻击特征的测试日志
python tools/genlog.py --lines 1000 --out access.log

# 分析它
python tools/loganalyze.py access.log
python tools/loganalyze.py access.log --top 10 -o report.txt
```

**输出示例：**

## 技术要点

### 三个工具的共同架构

```
  解析输入 → 生成任务 → 并发执行 → 收集结果 → 统一输出
```

端口扫描和目录扫描是 I/O 密集型（等网络），用 `ThreadPoolExecutor` 并发；日志分析是 CPU 密集型（解析文本），**不需要多线程**（GIL 限制）。

### 端口扫描器

- **`Port` 类**：`__init__` 里做范围校验，保证「非法端口对象无法存在」
- `@classmethod parse()` 解析 `22,80,8000-8010` 三种写法
- `__eq__` + `__hash__` 实现后用 `set` 去重（list 的 `in` 是 O(n)，set 是 O(1)，实测 **490 倍**差距）
- **两层防护**：启动前预检目标可达性（fail-fast），扫描中单个端口失败继续（keep-going）
- CIDR 用 `ipaddress` 展开，`net.num_addresses` 直接算规模（**优化前 18.42s → 优化后 0.21s**）

### 目录扫描器

- **只对本地靶场扫描**（目录扫描比端口扫描敏感得多）
- `allow_redirects=False` —— 不加就永远看不到 301/302
- `requests.Session` 复用连接 + 统一 User-Agent（默认 UA 是 `python-requests/2.34.2`，等于告诉服务器「我是脚本」）
- 扫描前预检目标（避免 71 个请求都连接失败）
- `functools.partial` 把 `session` / `timeout` 绑定到 worker，让 `executor.map` 只传任务数据

### 日志分析器

- **命名分组正则**提取 8 个字段；`(?: ...)?` 让 referer/UA 可选，**一个正则同时兼容 Common 和 Combined 两种日志格式**
- `urlsplit(...).path` 剥掉查询参数（否则 `/search?q=a` 和 `/search?q=b` 会被算成两个路径）
- **两层容错**：正则不匹配 + 时间解析失败，都计入「跳过行数」，不中断
- **先验证，后计数** —— 所有校验通过才进统计，保证数字一致
- 4 条检测规则：目录扫描（404 量）、暴力破解（登录路径频次）、扫描器 UA、敏感路径

### 日志生成器（测试数据）

- **按比例分配各类行数**（正常 70% / 目录扫描 15% / 暴力破解 5% / 敏感探测 3% / 扫描器 UA 2% / 损坏行 5%），损坏行用**减法**算，保证总数精确
- **攻击流量必须「时间聚集」** —— 真实扫描是 30 秒内打 150 个请求，而正常用户分散在 2 小时里。**不造出这个特征，基于时间窗口的检测规则就测不出效果**
- 6 种「损坏行」（截断 / 空行 / 缺括号 / 时间格式不同 / syslog 混入 / 只有 IP），**专门测分析器的容错路径**
- 生成后**按时间排序**（存 `(datetime, line)` 元组而非纯字符串）
- 打印「埋雷清单」，作为分析器的验收标准

## 踩过的坑（选一部分）

| 坑 | 现象 | 原因 |
|---|---|---|
| `except ValueError` 吞掉自定义异常 | 范围错误的报错变成了格式错误 | `PortParseError` 继承 `ValueError`，被同一个 `except` 抓走 |
| 对象没有 `__str__` | 输出变成 `<Port object at 0x...>` | Python 回退到默认表示 |
| `append` 之后才查重 | 所有合法端口都被误报「重复」 | 检查必须在添加之前 |
| 边遍历边 `append` | 死循环隐患 | 遍历列表时修改它 |
| `random.choices` 少了 `k=1` | 所有分支都走 `else`，**但不报错** | `choices` 返回列表，`'x' != ['x']` |
| `access.log` 加进 `.gitignore` 却还生效 | 文件仍被跟踪 | **忽略规则对已跟踪的文件无效**，要 `git rm --cached` |
| `requests.get` 的 `allow_redirects` | 永远看不到 3xx | 默认 `True`，自动跟随重定向 |
| Windows 上 `open()` 不写 encoding | 中文内容乱码/报错 | 默认用 GBK |
